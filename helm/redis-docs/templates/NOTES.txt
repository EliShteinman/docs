Redis Docs has been deployed!

{{- if .Values.ingress.enabled }}

Access the documentation at:
{{- range .Values.ingress.hosts }}
  http{{ if $.Values.ingress.tls }}s{{ end }}://{{ .host }}
{{- end }}

{{- else if .Values.route.enabled }}

Access the documentation via OpenShift Route:
  oc get route {{ include "redis-docs.fullname" . }} -n {{ .Release.Namespace }}

{{- else if contains "NodePort" .Values.service.type }}

Get the application URL by running:
  export NODE_PORT=$(kubectl get --namespace {{ .Release.Namespace }} -o jsonpath="{.spec.ports[0].nodePort}" services {{ include "redis-docs.fullname" . }})
  export NODE_IP=$(kubectl get nodes --namespace {{ .Release.Namespace }} -o jsonpath="{.items[0].status.addresses[0].address}")
  echo http://$NODE_IP:$NODE_PORT

{{- else if contains "LoadBalancer" .Values.service.type }}

Get the application URL by running:
  NOTE: It may take a few minutes for the LoadBalancer IP to be available.
  kubectl get --namespace {{ .Release.Namespace }} svc {{ include "redis-docs.fullname" . }} -w

{{- else if contains "ClusterIP" .Values.service.type }}

Access the documentation by running:
  kubectl --namespace {{ .Release.Namespace }} port-forward svc/{{ include "redis-docs.fullname" . }} 8080:{{ .Values.service.port }}

Then open http://localhost:8080 in your browser.

{{- end }}

{{- if .Values.search.enabled }}

Search is deployed. It indexes the site's own feed at startup, so the pod is not ready
until the index is built — a minute or two on a full corpus:
  kubectl --namespace {{ .Release.Namespace }} rollout status deploy/{{ include "redis-docs.fullname" . }}-search
{{- if not .Values.mirror.enabled }}
It indexes the documentation only. The mirrored sections are not deployed, so their
pages are deliberately absent from the results.
{{- end }}
{{- end }}

{{- if .Values.mirror.enabled }}

The mirrored redis.io sections are deployed as their own pod, and the site proxies
/blog/, /tutorials/, /customers/, /compare/, /solutions/, /technology/ and
/resources/architecture-diagrams/ to it.
{{- end }}

{{- if not .Values.mirror.enabled }}

The mirrored redis.io sections (blog, tutorials, customer stories, comparisons,
solutions, technology pages, architecture diagrams) are NOT deployed. The documentation
is complete without them: their sidebar entry and the links into them are removed in the
browser rather than leading to a 404. Set mirror.enabled=true to deploy them, and mirror
the redis-docs:*-mirror-unprivileged image alongside the main one.
{{- end }}
